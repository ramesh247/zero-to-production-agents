# 07 · Beyond text: images and PDFs as LLM input

Send an invoice image and a PDF report to Claude Haiku 5.5 and measure two things: what an image costs at different sizes and how small it can get before numbers come back wrong, and what you lose by extracting a PDF's text instead of sending the PDF.

**What you'll learn**
- Why a **400×500** invoice read every value correctly at **84% fewer tokens** than the 2400×3000 original
- What the model does when an image is too small to read (spoiler: it doesn't say so)
- Why text extraction answered **0/12** questions about a PDF's chart and scan, and what sending the PDF costs instead

## Quickstart
Needs an Anthropic API key. A full run costs **under 2 cents** on Claude Haiku 5.5.
```sh
git clone https://github.com/ramesh247/zero-to-production-agents.git
cd zero-to-production-agents/01-genai-llm-foundations/07-multimodal-inputs
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt jupyter
cp .env.example .env        # then paste your key
jupyter notebook notebook.ipynb
```

## Results from a real run (Claude Haiku 5.5, thinking off, 3 runs per setting)

**One 20-line invoice (62 values), downscaled:**

| Image size | Input tokens | Correct (of 62) |
|---|---|---|
| 2400×3000 | 5,337 | 62 |
| 1200×1500 | 2,885 | 62 |
| 800×1000 | 1,607 | 62 |
| 600×750 | 1,157 | 62 |
| **400×500** | **833** | **62** |
| 300×375 | 717 | 56-57 |
| 240×300 | 662 | 21-22 |
| 200×250 | 635 | 2-5 |

Below 400×500 the model still returned 20 well-formed lines and finished normally, with numbers like **90.15 read as 90.10**. No refusal and no warning.

**A 3-page PDF (text on page 1, a chart and a scanned table embedded as images):**

| Sent as | Input tokens | Text questions | Chart / scan questions | Cost per question set |
|---|---|---|---|---|
| Text extracted with `pypdf` | 678 | 12/12 | **0/12** (answered null) | $0.0001 |
| The PDF itself (`document` block) | 5,413 | 12/12 | **12/12** | $0.0006 |
